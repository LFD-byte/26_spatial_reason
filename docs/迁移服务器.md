# 迁移到新服务器

项目约 105 GB,但需要从旧服务器搬走的只有约 10 GB(其中 `outputs` 5.5 GB)。其余可以在新服务器上重新下载。

| 部分 | 怎么迁 | 大小 |
|---|---|---|
| 代码 | git | — |
| 环境 | 按 `envs/*.lock.txt` 重建(torch / vllm 按新驱动选版本) | — |
| 数据与结果:`data/processed` `data/embeddings` `data/traces` `data/raw/gene_maps` `outputs` `third_party` | `scripts/sync_project.sh`(rsync 增量 + 续传) | ~9.5 GB |
| 自训练模型 `data/models/{pca,expr,novae_ft,novae_scratch}`:HuggingFace 上没有,嵌入依赖它们 | 同上,默认同步 | ~630 MB |
| 下载来的模型权重(Qwen3、Novae、Nicheformer) | `scripts/download_models.sh` 从 HuggingFace 重新下载;新机器连不上 HF 时用 `sync_project.sh --with-models` | 70 GB |
| 原始数据 `data/raw` | 只有重新预处理(含 DLPFC 反卷积用的 snRNA 参考)才需要:`scripts/01_prepare_data.py` 重新下载,或 `--with-raw` | 26 GB |

## 1. 旧服务器:推代码、同步数据

```bash
git push -u origin feat/stage1-sft
bash scripts/sync_project.sh user@new-host:/path/to/26_spatial_reason --dry-run   # 先看要传哪些
bash scripts/sync_project.sh user@new-host:/path/to/26_spatial_reason
```

两台机器不能直接 ssh 时,经云存储中转(rclone 需先配置好 remote):

```bash
bash scripts/sync_project.sh myremote:bucket/26_spatial_reason --rclone   # 旧服务器上传
rclone copy myremote:bucket/26_spatial_reason /path/to/26_spatial_reason --progress   # 新服务器下载
```

训练还在跑时可以先同步一次,结束后再跑同一条命令,只传有变化的文件。

## 2. 新服务器:代码

```bash
git clone <repo-url> 26_spatial_reason && cd 26_spatial_reason
git checkout feat/stage1-sft
```

数据同步到这个目录下(`sync_project.sh` 的目标路径填它)。

## 3. 新服务器:环境

先看驱动支持的 CUDA 版本:`nvidia-smi` 右上角的 `CUDA Version`。torch 的 CUDA 版本不能高于它。
旧服务器驱动 535(CUDA 12.2),用的是 cu126;默认 PyPI 的 torch 是 cu13x,在旧驱动上无法使用 GPU。

| 驱动 CUDA Version | torch index |
|---|---|
| 12.2 – 12.5 | `https://download.pytorch.org/whl/cu126`(依赖 CUDA 12 次版本兼容,旧服务器实测可用) |
| ≥ 12.6 | `cu126` 或 `cu128` |
| ≥ 13.0 | 默认 PyPI 即可 |

### 训练环境 `spatial_reason`(Python 3.11)

```bash
conda create -n spatial_reason python=3.11 -y
conda activate spatial_reason
pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cu126   # 按上表换 index
echo "torch==2.14.1" > /tmp/constraints.txt                                    # 防止后续依赖把 torch 换掉
pip install -r envs/spatial_reason.lock.txt -c /tmp/constraints.txt
pip install -e . --no-deps
```

### 教师生成环境 `vllm`(Python 3.12,只在生成教师轨迹时需要)

```bash
conda create -n vllm python=3.12 -y
conda activate vllm
# 旧服务器用的是 GitHub release 的 cu129 wheel(在 CUDA 12.2 驱动上可用):
pip install https://github.com/vllm-project/vllm/releases/download/v0.32.0/vllm-0.32.0+cu129-cp38-abi3-manylinux_2_28_x86_64.whl
pip uninstall -y torchcodec   # 按 CUDA 13 编译,旧驱动上加载失败,而文本生成用不到
```

`envs/vllm.lock.txt` 是旧服务器上 vllm 环境的完整版本列表,依赖出问题时对照用。

脚本默认环境路径是 `~/software/anaconda3/envs/{spatial_reason,vllm}`。路径不同时用环境变量覆盖:
`TRAIN_ENV=... VLLM_PY=... bash scripts/run_stage1.sh`,`HF=... bash scripts/download_models.sh`。

## 4. 新服务器:模型

```bash
bash scripts/download_models.sh                # 全部 ~70 GB
bash scripts/download_models.sh --no-teacher   # 教师轨迹已同步过来、只做训练时,跳过 Qwen3-32B(62 GB)
```

网络受限时可以先设置 `export HF_ENDPOINT=https://hf-mirror.com`。

## 5. 验证

```bash
conda activate spatial_reason
python -m pytest -q tests                                  # 22 个测试
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.device_count())"
nvidia-smi topo -m                                         # 看两卡之间是否有 P2P(NV# / PIX 有,SYS 没有)
```

## 6. 接着跑

```bash
nohup bash scripts/run_stage1.sh > outputs/stage1/pipeline.log 2>&1 &
```

已完成的步骤会自动跳过;`outputs/` 里有 `checkpoint.pt` 的训练会续训。

## 已知问题

- **两卡无 P2P(topo 为 `SYS`)时,vLLM TP=2 会卡死或报非法访存**:要加 `NCCL_P2P_DISABLE=1`、`--enforce-eager`、
  `--disable-custom-all-reduce`。`run_stage1.sh` 已经加上。新服务器有 NVLink 时可以去掉 `--enforce-eager`,会快一些。
- 新服务器的 GPU 数量或显存不同:改 `configs/accelerate/ddp_2gpu.yaml` 的 `num_processes`;
  训练的 `global_batch_size` 固定,梯度累积会自动换算。单卡放不下 Qwen3-32B bf16(64 GB)时,教师改用 FP8 版本。
- `data/embeddings` 带 obs 校验和;如果在新服务器重新预处理,`data/processed` 变了,嵌入会被判为过期并要求重新提取。
